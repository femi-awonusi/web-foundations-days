# Day 8 Reflection

The most difficult concept in this course was understanding how different parts of a web application work together, particularly how databases, APIs and concurrent requests affect system reliability. I initially found it challenging to distinguish between checking whether a resource was available and guaranteeing that it remained available when multiple users requested it simultaneously. I overcame this by working through the database exercises, practising SQL transactions and constraints, and applying those concepts to the TicketHub design. I now understand why application-level checks alone cannot prevent double-booking and why the database must enforce critical rules.

Based on feedback received on my capstone, I would improve the clarity and completeness of the system design, particularly its error handling, security considerations and testing strategy. I would also strengthen the explanation of how the components interact under heavy traffic and test the design against concurrent reservation attempts, expired holds and delayed payment confirmations. These improvements would make the project more robust and demonstrate its behaviour under realistic conditions.

Next, I want to learn backend development in greater depth, especially building REST APIs, implementing authentication and integrating a relational database with an application server. I also intend to explore automated testing, deployment and monitoring. My goal is to progress from designing web applications to building, testing and deploying reliable applications that can handle real users and practical business requirements.
